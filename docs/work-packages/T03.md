## 转 ACCEPTED 的条件（阻塞项）

在目标 GPU 环境执行 `kernelagent probe` 且 cuda_kernel_launch 为 pass（当前环境三层限制：①宿主 VM 的 GPU-PV 拒绝设备内存分配（CUresult 0xc9）与结果回读（0xc0000006）；②嵌套 WSL 中驱动执行层 SIGSEGV；③真实物理卡待用户安装）。新卡就位后在物理机原生 Linux/Windows 或重配后的 WSL 复跑本命令即可完成验收。

## 环境发现（对后续包有影响）

1. 本 Windows 会话运行在虚拟机中，GPU 为 GPU-PV 透传：允许驱动查询/上下文/JIT/启动/同步，但拒绝设备内存分配（0xc9）与宿主回读（0xc0000006）。T04 worker、T07 计时必须运行在**直通真实 GPU**的环境。
2. 嵌套 WSL 的 GPU 库挂载在 VM 冷启动后存在竞态（曾观察到 /usr/lib/wsl/lib 短暂为空），且驱动执行层不稳定（SIGSEGV）——WSL 不适合作为 T04 worker 目标，除非在物理机上重配。
3. WSL 的 `ncu` 是 Windows 路径残留 shim，实际不可用——T15 需要原生 Linux NCU。

## 结论

- 是否满足本包全部必需检查：CPU 层全部满足；GPU 层两项检查已真实执行并产出精确诊断，但"小型探测成功"未达成（环境阻塞）。
- 与设计的偏差及 ADR：无关键接口偏离。实现说明：(1) 驱动检查在隔离子进程中执行——真实驱动库在受限环境会 SIGSEGV，隔离使探测主体存活并显式报告崩溃；(2) cuMemAlloc 失败时回退 cuMemAllocManaged（本机 managed 可分配、启动、同步，仅回读受限）；(3) ctypes 显式 argtypes——无原型时 Python int 按 32 位传参导致 64 位 size_t 高位为垃圾（实测致 cuMemAlloc 假失败）；(4) `evaluation` 无关：本包不改 domain。
- 仍未验证的范围：真实 PTX kernel 在可写读回的 GPU 上执行验证（即 GPU=PASS 的验收）；NCU 真实 profiling（T15）。
- 下一步：用户安装真实 NVIDIA 卡或提供 Linux GPU 环境后复跑 `kernelagent probe`；probe pass 后 T03 转 ACCEPTED 并解锁 T04。
