## 历史观察及证据限制

1. 修复前 native 报告记录 `cuMemAlloc=0xc9`、随后回读异常；WSL 报告记录 kernel child 退出 -11。这些是可追溯的历史观察，不再归因为 GPU-PV、虚拟化或具体硬件限制。
2. 审查发现 probe 当时把设备地址直接放进 `kernelParams`，而 API 要求每项指向主机参数存储；同时绑定了未版本化的旧内存函数名，却按现代 64 位 `CUdeviceptr` 声明。两项缺陷都足以污染原 GPU 结果。
3. 当前实现显式使用 `cuMemAlloc_v2`/`cuMemcpyDtoH_v2`/`cuMemFree_v2`、正确参数间接层与 cleanup 验证。只有在目标 Ubuntu + NVIDIA 环境复跑后，才能形成新的环境结论并解锁 T04。

## 结论

- 是否满足本包全部必需检查：CPU 层全部满足；GPU 层两项检查已真实执行并产出精确诊断，但"小型探测成功"未达成（环境阻塞）。
- 与设计的偏差及 ADR：无关键接口偏离。实现说明：(1) 驱动检查在隔离子进程中执行，异常退出转为显式 fail；(2) device allocation 失败时尝试 managed allocation，两类内存均用 `cuMemFree_v2` 清理；(3) ctypes 绑定与 CUDA 13.3 头文件的现代 ABI 对齐，kernelParams 指向主机端 `CUdeviceptr` 参数槽；(4) 命令超时/OSError 只使对应检查 fail，不中断整份报告。
- 仍未验证的范围：真实 PTX kernel 在可写读回的 GPU 上执行验证（即 GPU=PASS 的验收）；NCU 真实 profiling（T15）。
