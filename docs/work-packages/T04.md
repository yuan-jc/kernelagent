# T04：可信 GPU worker（下一实现包）

状态：TODO。依赖 T01、T03；T03 未验收时不接受父包。T04a 只提供已有进程机制。

## 目标与范围

在目标 Ubuntu + NVIDIA 上复用容器运行时和 NVIDIA Container Toolkit，构建可接收结构化请求、隔离候选并返回可信结果的 worker。不要自研容器或继续把进程组描述成沙箱。

先记录 ADR：运行时及镜像 digest、CUDA/驱动兼容性、用户/目录/设备/网络权限、GPU 分配、CPU/内存/磁盘/时间限额、输入输出协议与已有 Domain 映射。GPU 软件依赖单独锁定，控制端保持无 torch/Triton/模型 SDK 的 Domain。

父服务掌握请求身份、reference、正确性规则、计时协议和结果落盘。候选只能提供代码与允许的输出，不能通过 stdout、退出码或自写 JSON 决定正确性/晋升。禁网与只读可信输入必须由 OS 强制，而不是事后比较文件 hash。

## 建议按两个子步交付

1. **Linux 隔离与资源边界（CPU）**：最小容器执行、协议校验、只读可信卷、独立输出卷、禁网、非特权用户、资源上限、整个任务归属回收；故障注入与 cancel。
2. **GPU 请求通路（GPU）**：固定一个已知 CUDA/Triton smoke 输入，经真实隔离边界执行，由可信端验证输出，记录代码/输入/环境/协议身份和资源结果。KernelBench 原生 evaluator 对照在 T05，不借本包的简单 kernel 声称其已接通。

每个子步实现前创建可运行验收入口并冻结 fixture；子步通过不自动接受整个父包。任务包超出一轮时保存可恢复交接，不以新类骨架作为完成。

## 必需验收矩阵（待实现入口，当前全部 NOT_RUN）

| 类别 | 正反例与失败条件 |
|---|---|
| 协议 | request/candidate/input/protocol 身份匹配；错 hash、截断/未知消息、候选自报成功均不能成为可信成功 |
| 文件/权限 | reference 与父服务证据目录不可写；越界路径、链接/目录替换不能让父进程读写/删除可信目录；结果只从允许输出路径接收 |
| 网络/凭据 | 候选无法连接外网或取得控制端凭据；负例失败由真实 OS 边界观察 |
| 生命周期 | 正常、错误、超时、父载荷提前退出、setsid 后代、cancel、启动/回收失败均有结构化结果；作业结束无遗留可运行后代 |
| 资源 | CPU/内存/进程数/输出磁盘/时间限额触发时不能拖垮父服务；超限不转成正确分数；GPU 独占/共享策略记录 |
| GPU | 真实设备请求、已知输出独立验证；错误 kernel、权限/资源失败均有证据；不能用 mock 替代 |
| 可复现 | 干净 Ubuntu 环境按固定镜像运行；记录提交/镜像/驱动/GPU/输入/协议、命令、退出码、原始日志与 hash |

运行前将上述矩阵变成精确命令和测试入口。未实现的命令不得写 PASS，CI 的 Ubuntu CPU 成功不证明 GPU。T04 通过后按 T05 → T06/T07 推进；不在本包开发搜索、方法生成器、性能排名或 NCU 分析。
