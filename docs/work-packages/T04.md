# T04：可信 GPU worker

## 契约

- 状态：ACCEPTED（2026-09-13，目标 Ubuntu + NVIDIA 真机验收）。依赖 T01（ACCEPTED）、T03（ACCEPTED）；T04a 提供进程机制基线，不替代本包。
- 对应设计章节：§7、§9.2、§12。
- 边界决策：[ADR-0001](../adr/0001-trusted-worker-container-boundary.md)（Docker + NVIDIA Container Toolkit/CDI；镜像按 digest 锁定；非 root、禁网、只读输入、tmpfs 输出、cgroup 限额、GPU 按 UUID 独占）。
- 目标行为：候选代码只能在容器边界内执行；可信父端掌握请求身份、reference、正确性规则与结果落盘；候选退出码/stdout/自写 JSON 不构成正确性或晋升。
- 修改范围：`src/kernelagent/worker/`（新增容器执行器）、`tests/test_container_worker.py`、`examples/container_gpu_smoke.py`、本卡片与文档。
- 本包不包含：KernelBench 原生 evaluator 对照（T05）、计时协议（T07）、搜索/方法生成/NCU 分析。

## 结论

- 是否满足本包全部必需检查：是。C1–C10（CPU）、G1–G2（真实 GPU）、R1（全量回归）全部 PASS，全部在目标 Ubuntu + NVIDIA 真机执行；负向 GPU kernel（写 43）虽 exit 0 仍被父端拒绝，验证了"候选不能自证正确"。
- 与设计的偏差及 ADR：ADR-0001 修订一处——输出通道由 tmpfs 改为宿主 bind 目录 + 父端监视限额（实测发现容器退出后 tmpfs 随 mount namespace 销毁，`docker cp` 得到静默空结果，结果不可恢复）。
- 仍未验证的范围：容器执行器对多 GPU/并发请求的调度策略（本包为单卡串行声明）；docker daemon 自身漏洞不在威胁模型；stdout/stderr 与输出限额为 0.5 s 轮询而非内核级上限（内存/PID 限额由 cgroup 内核强制兜底）。
