# T04a：已有进程机制及复核边界

状态：READY_FOR_ACCEPTANCE。它是 T04 的离线子包，不能替代父包验收。

接口：`WorkerRequest -> execute -> WorkerOutcome`。具备私有随机目录、严格输入、环境过滤、日志有界读取、超时和错误结果、目录清理/保留策略。Windows 使用挂起启动、Job 归属后恢复；POSIX 使用独立进程组及回收。completed 只表示进程退出，不是评测 PASS。

CPU 复核入口：

```bash
uv run --locked kernelagent check --output artifacts/worker-cpu
uv run --locked python examples/worker_smoke.py
```

必要回归：路径遍历/可变输入拒绝、缺失 executable、Job 创建/绑定失败、父提前退出后回收后代、超时终止失败、部分日志打开失败、日志回读失败、目录清理失败。每项须检查结果语义与资源去留，不能只断言函数有返回值。最新测试与 CI 绑定见 [证据索引](../evidence/current.json)。

保留限制：POSIX setsid 脱离与 OS 强制隔离未覆盖；stdout/stderr 文件总量尚无生产级限额；环境变量过滤不是完整秘密隔离。目标 Ubuntu 复核及 T04 容器防线完成前，仅运行受控开发载荷。不要继续为它添加搜索、模型或 benchmark 业务。
